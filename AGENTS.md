## Engine public APIs (verified Sprint 11F)
- `SwingEngine(config).detect(candles) -> list[SwingPoint]` — fractal swing detection; needs `lookback` candles on each side to confirm a swing. Mutates `swing.evidence` (mutable SwingEvidence) but never the input candles.
- `MarketStructureEngine().analyze(swings) -> list[StructurePoint]`
- `StructureAnalysisEngine().analyze(structures) -> StructureAnalysis` — exposes `current_bias` / `previous_bias` (NOT `.bias`).
- `BOSEngine().analyze(analysis) -> BOSResult` — exposes `bos_type` (NOT `.type`).
- `CHOCHEngine().analyze(structures, analysis, bos) -> CHOCHResult` — exposes `choch_type` (NOT `.type`).
- `TrendEngine().analyze(analysis, bos, choch) -> TrendResult` — exposes `.state` (matches what ConfluenceEngine reads).
- `LiquidityEngine(config).detect(swings) -> list[LiquidityPool]`
- `LiquidityEventEngine(config).analyze(pools, candles) -> list[LiquidityEvent]`
- `ConfluenceEngine().analyze(analysis, bos, choch, trend, liquidity_events=None, reference_time=None) -> ConfluenceResult` — reads attributes DEFENSIVELY via getattr: `analysis.bias`, `bos.type`, `choch.type`, `trend.state`. Real model attribute names DIFFER (see above), so end-to-end wiring needs adapter views (see pipeline).
- `DecisionEngine().analyze(confluence) -> DecisionContext`
- `SignalEngine().analyze(decision, context=None) -> SignalResult` where `context` is `SignalContext(trigger_close, structure_break_level, liquidity_level, supplied_entry, reference_time)`. Entry precedence: supplied > trigger_close > structure_break > liquidity. Fallback stop = entry*0.98 (LONG) / *1.02 (SHORT); fallback target = entry +/- risk*2.0.
- `SignalValidationEngine().validate(signal, candles, max_candles=None) -> ValidationResult` — DEFAULT_MAX_CANDLES=50. Reads `signal.direction.value`, `entry_price`, `stop_loss`, `take_profit`. SignalResult works directly. Entry touch: `low <= entry <= high`.
- `PerformanceAnalyticsEngine().analyze(results: Iterable[ValidationResult]) -> PerformanceAnalytics` — never raises on empty input.

## Sprint 11F — Pipeline (added)

Walk-forward: at point T, analysis..signal see only `candles[:T+1]`; validation sees `candles[T+1:]`. One-active-signal policy: next signal allowed at `T + 1 + validation.candles_evaluated`. Suppressed points flagged via `PipelineEvaluationPoint.suppressed`.
- `src/engine/pipeline/datasets.py`: `trending_dataset()`, `flat_dataset()`, `minimal_dataset()`.

- `src/engine/research/regime.py`: `MarketRegimeEngine(config).classify(candles) -> MarketRegime`. Deterministic, intentionally simple: normalised ATR (volatility) gates first, then directional efficiency (net move / path length). Uses ONLY the supplied walk-forward slice; never reads future candles. `RegimeConfig` is mutable (window=20, min_history=10, configurable thresholds).
- `src/engine/research/segmentation.py`: `PerformanceSegmentationEngine(config).segment(pairs, dimension, candles=None, evaluation_indices=None) -> SegmentedPerformance` where `pairs` = `(SignalResult, ValidationResult)` tuples. Per-segment metrics DELEGATED to `PerformanceAnalyticsEngine` (no recomputation). Confidence/RR bucket thresholds configurable via mutable `SegmentationConfig`. REGIME dimension needs `candles` + `evaluation_indices` (walk-forward slices `candles[:T+1]`).
- `src/engine/research/sensitivity.py`: `ParameterSensitivityEngine(config).analyze(parameter_name, parameter_values, evaluator) -> ParameterSensitivityReport`. Generic — caller supplies evaluator returning `PerformanceAnalytics` or `PipelineResult` (projected via `.performance` / `.validation_results`). NO automatic overfitting: reports `best_value_by_expectancy` (descriptive, `best_value_descriptive=True`), `median_expectancy`, `expectancy_range`, `profitable_configurations`, `stability_ratio`, `sufficient_data` (>=2 configs). No `optimal`/`deploy` attribute.
- `src/engine/research/out_of_sample.py`: `OutOfSampleEngine(config).evaluate(candles, evaluator) -> OutOfSampleReport`. CHRONOLOGICAL split only (never shuffles); `OutOfSampleConfig.split_ratio` default 0.70. Degradation = oos − in_sample for expectancy/profit_factor/win_rate/drawdown + trade_count_change. Graceful on insufficient data / evaluator exceptions.
- `src/engine/research/leakage.py`: `LeakageAuditEngine(config).audit(result, candles=None) -> LeakageCheckResult`. 5 deterministic checks: (1) analysis at T within candle range, (2) validation begins after T, (3) no future candle supplied to analysis (validated via candles_evaluated ≤ future window), (4) out-of-sample isolation (caller-declared; warning when unconfirmed), (5) chronological indices/timestamps. `passed` iff no failures. Does NOT claim mathematical zero-leakage guarantee.
- `src/engine/research/research.py`: `ResearchEngine(config).analyze(result, candles, pipeline_evaluator=None, parameter_evaluator=None, label, metadata) -> ResearchReport`. Orchestrates all sub-engines; does NOT duplicate trading logic. Conclusions are DESCRIPTIVE only (never "strategy is profitable"); uses wording like "Positive historical expectancy observed in this dataset", "Out-of-sample performance degraded...", "Insufficient trades for reliable inference", "Parameter sensitivity appears high", "No leakage violations were detected by the implemented checks".
- `src/engine/research/__init__.py` re-exports the full public API (third orchestration exception after pipeline/reporting).
- `scripts/test_research.py`: demo producing the Research Robustness Report. `tests/test_research.py`: 64 tests (regime, segmentation, sensitivity, out-of-sample, leakage, ResearchEngine, immutability, end-to-end).

## Sprint 11I — Research & Robustness HARDENING (added)
This sprint hardens the research framework for serious strategy research WITHOUT adding ML, LLMs, broker integration, live trading or external APIs. It is purely research-methodology hardening. All changes are ADDITIVE and backward-compatible: no Sprint 11A–11H public API signature was changed, and all 419 prior tests still pass.

New engines (extend the existing `src/engine/research/` package):
- `src/engine/research/walk_forward.py`: `WalkForwardParameterEngine(config).evaluate(candles, parameter_name, parameter_values, evaluator) -> WalkForwardSelectionReport`. Makes the development / evaluation separation for parameter selection EXPLICIT and auditable. Chronologically splits candles into development `[:split]` and evaluation `[split:]` windows (non-overlapping). Evaluates EVERY candidate on the DEVELOPMENT window only -> `CandidateResult` list. Selects the descriptive best (highest DEVELOPMENT expectancy) -> `SelectedConfiguration` (`selected_from_development_data=True`, `selection_basis="development_expectancy"`). Evaluates ONLY the selected config on the EVALUATION window -> `out_of_sample_result`. `selection_isolated_from_evaluation=True` and `selection_verified=True` BY CONSTRUCTION (structural proof, not statistical). `WalkForwardEvaluator = Callable[[Sequence[OHLCVCandle], Any], Any]` (takes candles AND value, unlike the Sprint 11H `ParameterEvaluator` which takes only value). `WalkForwardConfig` mutable (split_ratio=0.70, min_development_candles=10, min_evaluation_candles=10, min_development_trades=1, selection_metric="expectancy"). Graceful on insufficient data / evaluator exceptions (never raises).
- `src/engine/research/robustness.py`: `ParameterRobustnessEngine(config).analyze(sensitivity_report) -> ParameterRobustnessReport`. Consumes a Sprint 11H `ParameterSensitivityReport` (composable — no recomputation of trading logic). Distinguishes DESCRIPTIVE BEST from ROBUST/STABLE: a config is `stable` only when `profitable AND near_median` (expectancy within `band = max(|median|*band_fraction, band_floor)` of the median). `descriptive_best` is the highest-expectancy value (descriptive only); `descriptive_best_is_robust` is True only when the descriptive best is also stable (NOT automatic). `highly_dependent_on_single_config` flags when the sweep's positive result rests on one config. `robust` requires sufficient data AND >=1 stable config. `RobustnessConfig` mutable (min_completed_trades=3, band_fraction=0.25, band_floor=0.1, min_configurations=2). Also exports `build_sensitivity_for_robustness(name, results)` helper to build a minimal sensitivity report from raw `ParameterResult` list for standalone use.

New/extended models in `src/engine/models/research.py` (all frozen, backward-compatible optional fields with defaults):

Leakage audit hardening (`src/engine/research/leakage.py`):
- `LeakageAuditEngine.audit(result, candles=None, context=None)` — new optional `context: LeakageAuditContext` (backward compatible: omit -> same 5-check audit, `checks_performed==5`).
- Base 5 checks now return structured `LeakageCheck` items with severities. Check 4 (OOS parameter isolation): when a `WalkForwardSelectionReport` is supplied, VERIFIED structurally (PASS); otherwise NOT_VERIFIED (never falsely PASS). Caller `out_of_sample_isolated=True` config accepted as PASS (caller assertion, not structural proof).

NEVER silently swallows a failure; NEVER reports PASS for an unprovable property.

## Sprint 11K — Research Dataset / Experiment Registry and Result Persistence Layer (added)
New package `src/engine/registry/` sits ABOVE the experiment layer (dependency: models ← intelligence ← pipeline ← reporting ← research ← experiment ← registry). The fifth orchestration package (after pipeline/reporting/research/experiment); its `__init__.py` re-exports the public API. The registry implements NO trading/validation/pipeline/research/comparison logic — every engine is reused as-is. All changes are ADDITIVE and backward-compatible: no Sprint 11A–11J public API signature was changed, and all 575 prior tests still pass.
- Goal: persist completed `ExperimentResult` objects in a structured, reproducible form and later retrieve/compare them WITHOUT rerunning the underlying trading pipeline. Designed as infrastructure, not as a trading strategy.
- `src/engine/models/registry.py`: frozen+slots registry models + `SCHEMA_VERSION = 1` (module constant). `ExperimentRecordHeader` (schema_version + experiment_id), `PersistedExperimentRecord` (header + reconstructed `ExperimentResult` + canonical JSON text + raw parsed mapping).
- `src/engine/registry/exceptions.py`: `ExperimentPersistenceError` (base) + `ExperimentNotFoundError`, `ExperimentAlreadyExistsError`, `ExperimentIntegrityError`, `UnsupportedSchemaVersionError`. No errors swallowed silently.
- `src/engine/registry/serialization.py`: deterministic, self-describing JSON serialization. `serialize_experiment(result) -> str` (sorted-key canonical JSON), `deserialize_experiment(payload) -> ExperimentResult`, `parse_record(payload) -> ExperimentRecordHeader` (cheap header-only parse), `canonical_json(payload) -> str`, `serialize_experiment_bytes`. Every non-primitive value carries a small type tag (`__type__` dataclass / `__enum__` / `__datetime__` / `__tuple__` / `__engine__` / `__bytes__`) so the deserializer reconstructs the EXACT model type without parsing type annotations. Historical experiment selection is DESCRIPTIVE ONLY and must never be presented as predictive; an experiment with insufficient evidence must NEVER be promoted.
- `src/engine/models/selection.py`: frozen+slots selection models + `SELECTION_SCHEMA_VERSION = 1` (separate from experiment `SCHEMA_VERSION` and suite `SUITE_SCHEMA_VERSION` because a selection decision is a structurally different artifact). Enums: `SelectionStatus` (NOT_ELIGIBLE/CANDIDATE/SELECTED/REJECTED — the explicit promotion status making evidence gating STRUCTURAL, not merely reported), `SelectionType` (EXPERIMENT/SUITE). Models: `SelectionCriteria` (explicit, configurable, all-optional criteria — `require_evidence_status`, `min_expectancy`, `min_total_r`, `max_drawdown_r`, `require_robust`, `require_oos_evidence`, `require_reproducible`, `min_completed_trades`; `is_default` property), `RejectionReason` (entity_id, status, reason, evidence_status), `SelectionCandidate` (read-only projection with metrics + `eligible` + `status` + `rejection_reason`; `has_oos_evidence` property), `SelectedResult` (entity_id, label, selection_type, rationale), `PromotionDecision` (promoted, selected, rationale), `SelectionResult` (selection_id, label, selection_type, criteria, candidates tuple, rejected tuple, selected, promotion, conclusions, metadata; `has_selected`/`all_evaluated`/`candidate_count`/`selected_entity_id` properties).
- Evidence gating (STRUCTURAL): INSUFFICIENT experiment → NOT_ELIGIBLE, can NEVER become CANDIDATE or SELECTED. PARTIAL experiment → NOT_ELIGIBLE, can NEVER become SELECTED (provisional only). SUFFICIENT experiment → eligible to become CANDIDATE. A suite with no SUFFICIENT member → NOT_ELIGIBLE (a suite is never selected merely because it contains a high-performing insufficient member). When no eligible SUFFICIENT candidate exists, `selected=None` — a winner is NEVER manufactured.
- Missing evidence is NEVER treated as positive evidence: `require_robust=True` rejects `robust is None` (missing robustness) AND `robust is False`; `require_oos_evidence=True` rejects the absence of OOS evidence (`oos_expectancy is None` or `oos_trades == 0`); `require_reproducible=True` rejects `reproducible is False`.
- Candidate rules: a SUFFICIENT candidate becomes CANDIDATE when it satisfies ALL active criteria (logical AND); it becomes REJECTED otherwise with the specific failing criterion recorded as the rejection reason. Deterministic ranking priority among CANDIDATEs: (1) sufficient evidence, (2) robustness (robust first; missing NOT treated as robust), (3) OOS evidence (has OOS first; missing NOT treated as successful OOS), (4) expectancy (higher), (5) total R (higher), (6) lower maximum drawdown, (7) reproducibility (reproducible first), (8) entity id ascending — DETERMINISTIC tie-break, NO random selection. Two identical persisted datasets always produce the same selected entity.
- `src/engine/selection/identity.py`: `SelectionIdentity(selection_type, criteria, label, metadata)` — deterministic identity; `selection_id = "sel-" + sha256[:16]` of canonical representation (reuses Sprint 11J `_canonicalize` helper). Same identity → same id; changing criteria/type/label/metadata → different id. No timestamps.
- `src/engine/selection/core.py`: shared selection core (`_is_eligible`, `_evaluate_criteria`, `_rank_key`, `build_selection_result`) operating on the unified `SelectionCandidate`. Evidence gating + criteria evaluation + deterministic ranking + descriptive conclusion generation. No duplicated logic.
- `src/engine/selection/engine.py`: `SelectionEngine(registry).select(criteria, label="", metadata=None) -> SelectionResult`. Loads persisted experiments via `registry.list()` + `registry.load_many()` (persisted data ONLY; NEVER invokes `HistoricalEvaluationPipeline.evaluate` or `ExperimentRunner.run`). Projects each `ExperimentResult` to a `SelectionCandidate` and delegates to the shared core.

  - DOJI (single, NEUTRAL): `body/range <= 0.1` when range>0, OR zero-range candle (open==high==low==close). score = `1 - body/range` (zero-range -> 1.0).
  - HAMMER (single, BULLISH): `body>0 AND lower_wick >= 2*body AND upper_wick <= body`. score = `min(lower_wick/(2*body), 1)`.
  - SHOOTING_STAR (single, BEARISH): mirror — `body>0 AND upper_wick >= 2*body AND lower_wick <= body`. score = `min(upper_wick/(2*body), 1)`.

  - BEARISH_ENGULFING (two, BEARISH): mirror. score same formula.
  - INSIDE_BAR (two, NEUTRAL): `prior.range>0 AND current.high <= prior.high AND current.low >= prior.low AND current.range < prior.range` (strictly smaller). score = `1 - current_range/prior_range`.
  - `score` is a deterministic SHAPE-QUALITY metric in [0,1] derived ONLY from explicit measurements — NOT a confidence/probability.
- Historical / look-ahead safety (STRUCTURAL): a pattern attributed to index T uses only `candles[T]` (single-candle) and `candles[T-1]` (two-candle). No pattern reads future candles. The base detector NEVER sets `confirmed=True` (confirmation would need future data). Regression tests prove: (a) appending/mutating candles after T leaves pattern(T) unchanged, (b) detecting on `candles[:T+1]` yields the same patterns at T as detecting on the full series, (c) a two-candle pattern at T is unaffected by mutating candle T-2.

Sprint 11R does NOT build trade validation, BUY/SELL signals, profitability prediction, ML, LLM, or live trading. The output of Sprint 11R is a TRADE CANDIDATE, not a trade. It is the third step of the separated concern pipeline: (1) MARKET OBSERVATION (11O/11P) -> (2) SETUP IDENTIFICATION (11Q) -> (3) TRADE CANDIDATE GENERATION (11R) -> (4) TRADE VALIDATION (future) -> (5) SIGNAL/EXECUTION (future). All changes are ADDITIVE and backward-compatible: no Sprint 11A-11Q public API signature was changed, and all 1092 prior tests still pass.
- Reuses EXISTING intelligence (NOT duplicated): SetupAssessment (Sprint 11Q classification + confluence_score + structured EvidenceItem supporting/conflicting views) and MarketContext (Sprint 11P support_resistance levels + range state + trend). Sprint 11R adds the candidate promotion gate + entry/stop/target derivation + risk/reward computation + conservative setup-type classification on top.
- New models `src/engine/models/trade_candidate.py` (frozen+slots): enums CandidateDirection (LONG/SHORT/NONE — deliberately separate from SignalDirection since a candidate is not yet a signal), CandidateStatus (NO_CANDIDATE/WATCH/CANDIDATE), SetupType (TREND_CONTINUATION/BREAKOUT/STRUCTURE_CONTINUATION/RANGE_REJECTION/SETUP_CANDIDATE — only the justifiable types are populated; SETUP_CANDIDATE is the conservative generic fallback, RANGE_REJECTION reserved for a future explicit range-setup policy); model TradeCandidate (timestamp, evaluation_index, direction, status, setup_type, setup_classification [reused 11Q SetupClassification], entry_reference, stop_reference, target_reference, risk_distance, reward_distance, risk_reward_ratio, confluence_score, supporting_evidence/conflicting_evidence [reused 11Q EvidenceItem tuples], candle_evidence/market_trend/market_structure/location/range_context [reused 11Q labels], reason; properties is_candidate, geometry_complete). `__post_init__` validates internal consistency: a CANDIDATE must carry a directional intent (not NONE); directional geometry ordering (LONG requires stop < entry < target, SHORT the mirror); risk/reward consistency with entry/stop/target and direction; positive risk/reward when populated; ratio == reward/risk. The engine never produces inconsistent states; the check guards against hand-construction bugs. Optional fields use None so "unavailable"/"invalid" is never silently a real value.
- New config `src/engine/config/trade_candidate_config.py` (frozen+slots, validated): TradeCandidateConfig — min_confluence_for_candidate=3 (mirrors 11Q min_supporting_for_potential_setup default so the candidate layer does not silently weaken the setup layer's evidence bar), allow_range_setups=False (conservative — a range is not treated as a directional trade setup by default; when True a POTENTIAL_SETUP that is IN_RANGE may still be promoted), min_risk_reward_ratio=None (optional gate; a candidate whose geometry is complete but whose R:R falls below the threshold is downgraded to WATCH; incomplete geometry is NOT rejected by this gate — reported honestly instead).
- New engine `src/engine/intelligence/trade_candidates.py`: TradeCandidateEngine(config).generate(assessment, market_context, index, timestamp, close_price) -> TradeCandidate. Deterministic, pure, future-leakage safe (reads ONLY the already-computed SetupAssessment + MarketContext, both derived from candles[:T+1], plus the trigger close price as a scalar — it inspects no candles directly). intelligence/__init__.py stays intentionally empty — import via `from engine.intelligence.trade_candidates import TradeCandidateEngine`.
  - DESIGN PRINCIPLE — reuse, do not re-invent: NO separate scoring system. The candidate layer reuses the 11Q SetupClassification + confluence_score verbatim plus the structured EvidenceItem supporting/conflicting views.
  - STATUS MAPPING (reuses 11Q classification): NO_SETUP -> NO_CANDIDATE (direction mapped from setup direction, likely NONE, no geometry); WATCH -> WATCH (direction mapped from setup direction, NO geometry — a watch is not a trade candidate); POTENTIAL_SETUP -> apply the conservative promotion gate.
  - PROMOTION GATE (POTENTIAL_SETUP is NOT automatically a CANDIDATE): requires (a) directional bias LONG/SHORT (not NEUTRAL/UNKNOWN -> WATCH), (b) confluence_score >= min_confluence_for_candidate (else WATCH), (c) NO disqualifying conflicting evidence (len(conflicting)>0 -> WATCH — no automatic candidate), (d) not range-blocked when allow_range_setups=False (IN_RANGE -> WATCH). Only when ALL pass -> CANDIDATE.
  - ENTRY/STOP/TARGET METHODOLOGY (objective, point-in-time, no future candles): entry = trigger candle close (close_price scalar); LONG stop = nearest support (sr.support) if support < entry else None (below a recent confirmed swing low); SHORT stop = nearest resistance (sr.resistance) if resistance > entry else None (above a recent confirmed swing high); LONG target = next resistance (sr.resistance) if resistance > entry else None (opposing structural level); SHORT target = next support (sr.support) if support < entry else None. If a level is absent or on the wrong side of the entry, the reference is explicitly None (unavailable) rather than invented.
  - RISK/REWARD: LONG risk = entry - stop, reward = target - entry; SHORT risk = stop - entry, reward = entry - target. If entry/stop/target any None -> all None. If risk <= 0 or reward <= 0 (non-positive / wrong-side geometry) -> all None (rejected, never manufactured). ratio = reward/risk only when both > 0. geometry_complete property = entry/stop/target present AND risk>0 AND reward>0 AND ratio present.
  - SETUP TYPE (conservative, deterministic, evaluated in order): LONG + ABOVE_RESISTANCE -> BREAKOUT; LONG + NEAR_SUPPORT + trend aligned -> TREND_CONTINUATION; LONG + NEAR_SUPPORT + trend not aligned -> STRUCTURE_CONTINUATION; else SETUP_CANDIDATE. SHORT mirror (BELOW_SUPPORT -> BREAKOUT; NEAR_RESISTANCE + trend aligned -> TREND_CONTINUATION; NEAR_RESISTANCE + trend not aligned -> STRUCTURE_CONTINUATION; else SETUP_CANDIDATE). Non-candidate points -> SETUP_CANDIDATE (generic). The system never pretends to distinguish a setup type it cannot reliably determine from the 11O-11Q evidence.

## Sprint 11S — Trade Candidate Ranking & Decision Intelligence (added)
This sprint builds the next TRADING-INTELLIGENCE layer (after Sprint 11R trade candidate generation): a deterministic, descriptive DECISION over one or more trade candidates that ranks them by technical-evidence strength/completeness and identifies the strongest (PREFERRED) candidate. Sprint 11S does NOT build trade validation, BUY/SELL signals, profitability prediction, probability of success, ML, LLM, broker integration, order execution, live trading, or portfolio management. The output of Sprint 11S is a DECISION/RANKING, not a trade. It is the fourth step of the separated concern pipeline: (1) MARKET OBSERVATION (11O/11P) -> (2) SETUP IDENTIFICATION (11Q) -> (3) TRADE CANDIDATE GENERATION (11R) -> (4) CANDIDATE RANKING/DECISION (11S) -> (5) TRADE VALIDATION (future) -> (6) SIGNAL/EXECUTION (future). All changes are ADDITIVE and backward-compatible: no Sprint 11A-11R public API signature was changed, and all 1164 prior tests still pass.
- Reuses EXISTING intelligence (NOT duplicated): the Sprint 11R TradeCandidate (direction, status, setup_type, confluence_score, supporting_evidence/conflicting_evidence, entry/stop/target/risk/reward/risk_reward_ratio, geometry_complete, candle/market_trend/market_structure/location/range_context labels). Sprint 11S adds the decision-scoring + classification + deterministic ranking layer on top. It does NOT recompute candle patterns, market context, setups or candidates.
- Decision classification is DELIBERATELY DISTINCT from Sprint 11R's CandidateStatus (NO_CANDIDATE/WATCH/CANDIDATE): DecisionClassification = REJECTED / WATCH / QUALIFIED / PREFERRED. 11R describes candidate *generation*; 11S describes candidate *decision/ranking*. The two are related but not identical: a generated CANDIDATE may, after ranking, be classified REJECTED/WATCH/QUALIFIED/PREFERRED.

Deterministic, pure, future-leakage safe (reads ONLY the already-computed TradeCandidate, itself derived from candles[:T+1]; inspects no candles directly). intelligence/__init__.py stays intentionally empty — import via `from engine.intelligence.trade_decision import TradeDecisionEngine`.
  - DESIGN PRINCIPLE — descriptive evidence strength, NOT probability: the Decision Score is an integer [0,100] = transparent sum of named components (trend/structure/candle/location/geometry/risk_reward/no_conflict). It is NEVER a probability of success or profitability prediction.
  - DESIGN PRINCIPLE — reuse, do not re-invent: reconstructs each evidence source's alignment relative to the candidate direction from the 11R candidate's supporting/conflicting EvidenceItem subsets plus per-source labels (ALIGNED if in supporting; CONFLICTING if in conflicting; ABSENT if label is the absence sentinel e.g. "UNKNOWN"/"none"; else NEUTRAL). NO 11R model modified.
  - SCORING: each directional source contributes a share of its weight (ALIGNED=full; NEUTRAL=neutral_fraction*weight; CONFLICTING/ABSENT=0). Geometry: complete=full; entry-only (no stop/target)=neutral_fraction share; none=0. Risk/reward: ratio>=good=full; >=min=half; <min or absent=0. No-conflict: 0 conflicts=full; else 0.
  - CLASSIFICATION: base from score thresholds, then CAPS (each can only reduce): (a) no directional bias (NONE) / NO_CANDIDATE status / no entry -> REJECTED; (b) 11R WATCH status -> capped at watch_status_max_classification; (c) conflicting evidence -> capped at conflict_max_classification (so conflict can never automatically produce PREFERRED by default); (d) require_geometry_for_preferred && incomplete geometry -> capped at QUALIFIED.   - RANKING (multiple candidates, core requirement): deterministic sort by _ranking_key (strongest-first): (1) classification rank desc, (2) decision score desc, (3) confluence score desc, (4) geometry-complete first, (5) risk/reward ratio desc (absent last), (6) fewer conflicting sources, (7) direction order LONG<SHORT<NONE, (8) evaluation index asc, (9) entry reference asc. Ranks are 1-based and UNIQUE (no two share a rank). preferred = rank-1 IFF PREFERRED — a winner is NEVER manufactured (None when none PREFERRED). No random behaviour; identical inputs always produce identical rankings.

## Sprint 11T — Trade Opportunity Filtering & Ranking (added)
This sprint builds the next TRADING-INTELLIGENCE layer (after Sprint 11S trade candidate ranking/decision): a deterministic, descriptive TRADE OPPORTUNITY filter/ranker that answers "Given all trade candidates available at a point in time, which opportunities are actually worth surfacing?" Sprint 11T does NOT build trade validation, BUY/SELL signals, profitability prediction, probability of success, ML, LLM, broker integration, order execution, live trading, or portfolio management. The output of Sprint 11T is a TRADE OPPORTUNITY view, not a trade. It is the fifth step of the separated concern pipeline: (1) MARKET OBSERVATION (11O/11P) -> (2) SETUP IDENTIFICATION (11Q) -> (3) TRADE CANDIDATE GENERATION (11R) -> (4) CANDIDATE RANKING/DECISION (11S) -> (5) TRADE OPPORTUNITY FILTER (11T) -> (6) TRADE VALIDATION (future) -> (7) SIGNAL/EXECUTION (future). All changes are ADDITIVE and backward-compatible: no Sprint 11A-11S public API signature was changed, and all 1251 prior tests still pass.
- Reuses EXISTING intelligence (NOT duplicated): the Sprint 11S `TradeDecision` (classification, decision_score, geometry_complete, confluence_score, supporting_count, conflicting_count, risk_reward_ratio, candidate ref). Sprint 11T adds the opportunity-eligibility + ranking + status layer on top. It does NOT recompute candidates, decisions, scores, classifications, geometry or risk/reward. The `TradeDecision` is retained BY REFERENCE.
- DESIGN PRINCIPLE — DISTINCT from Sprint 11S: 11S answers "How strong is this candidate?" (per-candidate decision classification + score). 11T answers "Should this candidate actually be surfaced as the best available trade opportunity at this evaluation point?" (eligibility filter + relative ranking + opportunity status). `OpportunityStatus` (NO_OPPORTUNITY/WATCH/ALTERNATIVE_OPPORTUNITY/BEST_OPPORTUNITY) is DELIBERATELY DISTINCT from `DecisionClassification` (REJECTED/WATCH/QUALIFIED/PREFERRED).

Validation: non-negative score, positive R:R when set, non-negative confluence, max_surfaced>=1, non-empty allowed sets.
- New engine `src/engine/intelligence/trade_opportunity.py`: `TradeOpportunityEngine(config).evaluate(decision, index, timestamp) -> TradeOpportunity` (standalone eligibility + provisional status) and `.rank(decisions, index, timestamp) -> TradeOpportunityRanking`. Deterministic, pure, future-leakage safe (reads ONLY the already-computed TradeDecision, itself derived from candles[:T+1]; inspects no candles directly). intelligence/__init__.py stays intentionally empty — import via `from engine.intelligence.trade_opportunity import TradeOpportunityEngine`.
  - ELIGIBILITY: a candidate must pass ALL active gates (candidate_status, decision_classification, decision_score, optional geometry, optional risk_reward [missing NOT rejected], optional conflict disqualification). Each gate recorded as an `EligibilityReason`. NO_CANDIDATE never eligible; REJECTED never eligible.
